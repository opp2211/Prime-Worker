## О проекте

Prime Worker — backend-сервис на Java/Spring Boot, который автоматически собирает рыночные данные из нескольких внешних источников, рассчитывает прикладные курсы и записывает результат в Google Sheets.

Проект решает реальную рабочую задачу: вместо ручного мониторинга P2P-площадок, маркетплейсов и игровых торговых страниц приложение регулярно обновляет таблицу актуальными значениями. Сервис развернут на VPS, работает по расписанию и может запускаться вручную через административный HTTP endpoint.

Для меня этот проект — пример практичной backend-разработки: работа с внешними API, HTML-парсингом, сетевыми таймаутами, конфигурацией через окружение, Docker-деплоем, CI/CD и тестами вокруг бизнес-логики.

## Источники данных

Сейчас используются несколько независимых источников:

* Bybit P2P — курсы USDT к RUB и KZT через API.
* Binance P2P — курс USDT к CNY.
* FunPay, G2G, DD373 — цены игровых ценностей с пересчетом в рубли.
* Google Sheets API — запись рассчитанных значений и времени обновления.

## Возможности

* Автоматический сбор данных по расписанию каждые 2 минуты.
* Ручной запуск обновления через `POST /admin/prime-task/run`.
* Нормализация значений через `BigDecimal` с контролируемым округлением.
* Разделение клиентов внешних источников и бизнес-расчетов.
* Обработка таймаутов и некорректных ответов для G2G с безопасным fallback.
* Поддержка Google Sheets как понятного операционного интерфейса для результата.
* Docker/Docker Compose деплой на сервер.
* CI/CD через GitHub Actions.

## Архитектура

Код разделен по зонам ответственности:

* `integration` — клиенты P2P-интеграций Bybit и Binance.
* `funpay`, `dd373`, `g2g` — отдельные сервисы для маркетплейсов и HTML/API источников.
* `service` — расчет итоговых значений и координация источников.
* `sheet` — запись данных в Google Sheets.
* `task` — scheduled job для регулярного обновления.
* `web` — административный endpoint для ручного запуска.
* `domain` — доменные модели курсов и P2P-запросов.

Такое разделение упрощает замену источников, тестирование бизнес-логики и локализацию изменений при изменении внешнего API или HTML-разметки.

## Качество и инженерные решения

В проекте сделан акцент на поддерживаемость, а не только на «получить данные любой ценой»:

* внешние интеграции изолированы от расчетной логики;
* для денежных значений используется `BigDecimal`;
* сетевые операции ограничены таймаутами;
* нестабильные источники покрыты fallback-логикой там, где это допустимо;
* чувствительные параметры передаются через переменные окружения и secrets;
* сборка и тесты запускаются в CI;
* деплой автоматизирован через GitHub Actions и Docker Compose.

## Конфигурация

Основные параметры задаются через переменные окружения:

```env
SPREADSHEET_ID=
BYBIT_API_KEY=
BYBIT_API_SECRET=
```

Для доступа к Google Sheets нужен service account файл:

```text
src/main/resources/secrets/google-credentials.json
```

Файл с credentials не должен попадать в репозиторий.

## Запуск

Локальная сборка и тесты:

```bash
./mvnw test
```

Запуск приложения:

```bash
./mvnw spring-boot:run
```

Запуск через Docker Compose:

```bash
docker compose up -d --build
```

По умолчанию приложение слушает порт `8081`.

## CI/CD

GitHub Actions pipeline выполняет:

* сборку проекта на JDK 21;
* запуск тестов;
* подготовку Google credentials из repository secrets;
* деплой на VPS для ветки `master` или ручного `workflow_dispatch`;
* перезапуск контейнера через Docker Compose.
